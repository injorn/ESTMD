# การใช้งาน Matrix ตามรูปแบบการส่งมอบ

Branch: `codex/historical-matrix-profiles`

## วิธีใช้งาน

1. เปิดโครงการ → ขั้น3 “Key รายการ” เลือกรูปแบบการส่งมอบต่อ Phase: พัฒนาเอง, SAP, กำกับ Vendor หรือ Migration/Rollout งานเดิมเริ่มที่ “สูตรเดิม” เพื่อรักษายอดที่เคยคำนวณ
2. พัฒนาเองใช้ Matrix เดิมตามกิจกรรม/หน่วยนับ ส่วน SAP/Vendor/Migration ลง MD รวมของ work package ตามบทบาท ค่าอัตโนมัติที่ไม่เคยแก้จะเริ่ม0เมื่อเปลี่ยนเป็น direct profile; ค่า manualเดิมยังเก็บไว้ ต้องตรวจว่าเหมาะกับรูปแบบใหม่
3. เปิด “แก้รายการ / แรงงาน / แหล่งอ้างอิง” ในรายการ เลือกบทบาท กรอก MD ก่อนปรับงบ แยก Commercial MD และ Actual MD ช่องว่างหมายถึงยังไม่ทราบ ไม่ใช่0 สามารถบันทึกงานไม่คิดเงินได้
4. กรอกไฟล์/ชีต/เซลล์และข้อเท็จจริงรองรับระดับ แล้วติ๊กยืนยัน Baseline การแก้แรงงาน/รายการ/รูปแบบจะยกเลิกการยืนยันที่เกี่ยวข้องเพื่อให้ทบทวนใหม่
5. ขั้น4 “ทีม & อัตรา” เลือกบทบาทที่จะรวมในสรุป ใช้ joint role เช่น BA/Tester เมื่อเอกสารไม่แยกแรงงาน ไม่ลงยอดเดียวกันเต็มจำนวนทั้งBAและTester บทบาทเพิ่มเติมเริ่มอัตรา0จนระบุราคาเอง
6. ขั้น5ตรวจยอดและ Export Excel ชีตหลักรวม Baselineทั้งหมด แต่ค่าใช้จ่ายใช้เฉพาะ MDที่คิดเงิน ชีต `Effort Evidence` แสดงรูปแบบ หน่วย จำนวน บทบาท Baseline/Commercial/Actual แหล่งอ้างอิงและสถานะยืนยัน

## กติกาสูตร

- กลุ่ม Matrix ใช้ค่าต่อหน่วย × จำนวน × stack/modifierเฉพาะบทบาทที่กำหนด งานต่อโครงการยังนับ1
- กลุ่ม SAP/Vendor/Migration ไม่ใช้ DEV ratio และไม่คูณ MDที่กรอกด้วยจำนวนอีก
- MDที่ยืนยันกรอกใหม่ใน roleแบบphase ใช้แทนratioสำหรับroleและphaseนั้น ไม่บวกซ้ำ กรอก0โดยตั้งใจได้
- ช่อง manualเก่าที่สูตรlegacyเคยละไว้ยังไม่เข้ายอดโดยอัตโนมัติ ต้องบันทึกยืนยันใหม่ หรือเลือก self developmentเพื่อใช้กติกาใหม่
- โครงการผสมไม่แสดงเป้าratioทั่วทั้งโครงการที่ทำให้เข้าใจผิด
- การเปลี่ยนstackเก็บmanualoverrideไว้ ปุ่มตั้งกลับมาตรฐาน resetเฉพาะกลุ่มMatrix ไม่ล้างแรงงานdirect
- Commercial และ Actualไม่ถูกนำมาคำนวณBaselineหรือค่าใช้จ่ายของBaseline

## สอบเทียบ

เปิด Standard Matrix → “วิธีประเมิน & สอบเทียบ” → ดาวน์โหลด JSON `/api/evaluation/calibration`

รายงานใช้รายการที่มี Baselineยืนยัน, source, level facts, qty>0 และ MDmanualของroleที่มีช่องMatrixและscopeitem แยกprofile/activity/role/level/unit แสดงmedian/IQR,จำนวนตัวอย่าง/โครงการ,MAE,signed biasและยอดรายโครงการ หักstackจากrateต่อหน่วยก่อนเทียบ ข้อมูลที่ใช้sourceเดียวกันสำหรับactivity/role/levelเดิมจะถูกกันซ้ำ

รายการdirectไม่เอาไปปรับgenericMatrix และ MDอัตโนมัติไม่ใช้เป็นคำตอบอ้างอิงของสูตรตัวเอง ผลรายงานเป็นข้อมูลเพื่อทบทวน ยังไม่เขียนกลับMatrixและยังไม่มีผลvalidationจากชุดโครงการที่กันไว้ การจับข้อความsourceช่วยกันการกรอกซ้ำ แต่ไม่รับรองว่าsourceชื่อคนละชื่อไม่ใช่เอกสารเดียวกัน เจ้าของข้อมูลยังต้องตรวจไฟล์GRC/RCPและกระทบยอดSmart Search

## การอัปเกรด

สำรอง SQLiteก่อนรัน `npm run db:migrate` แล้วรัน `npm run db:evidence-roles` เพื่อเพิ่มบทบาทเสริมโดยไม่seedทับค่าMatrix/อัตราเดิม ฐานข้อมูลในworkspaceนี้สำรองและอัปเกรดแล้ว

Migrations: `0008_lean_payback.sql` และ `0009_normal_wrecking_crew.sql` เพิ่มคอลัมน์พร้อมค่าdefaultที่รักษาสูตรเดิม งานoldoverrideใช้flagแยกจากexpliciteffortใหม่

การเปลี่ยนprogramไม่ได้import24workbookลงฐานข้อมูล ไม่rewriteworkbook และไม่ได้เรียกTypeSafeAPIหรือส่งข้อมูลออกนอกเครื่อง ค่าL/M/Hคงเดิม; TypeSafeใช้ช่วยตัดสินprofile/activity/factsได้ในขั้นต่อไปเมื่อมีชุดตรวจยืนยัน
