# Jev ช่วยเสนอการประเมินรายการจาก Excel

สถานะ: สรุปข้อตกลงจาก grill-with-docs แล้ว วันที่ 2 ตุลาคม 2026 ยังไม่มีการเรียก API หรือส่งรายการงานออกจากระบบในรอบนี้ การพัฒนาจะเตรียมระบบและทดสอบด้วยข้อมูลจำลองก่อน เนื่องจากยังไม่มี API key

## ข้อตกลงที่ยืนยันแล้ว

1. เจ้าของงานเลือกให้ Jev เสนอ Activity และระดับ L/M/H ผู้ประเมินเป็นผู้ตรวจและยอมรับก่อนใช้ผล ไม่ยืนยันอัตโนมัติด้วย confidence และไม่ให้ AI สร้างตัวเลข MD โดยตรง
2. ข้อมูลประกอบคือรายละเอียดงาน, Phase, สิ่งส่งมอบ, รูปแบบงาน, Technology Stack และเกณฑ์ Matrix ใช้เฉพาะรายการที่ผู้ใช้เลือกวิเคราะห์ ไม่ส่งทั้งชีตเป็นค่าเริ่มต้น
3. เมื่อข้อมูลไม่พอ ให้เสนอเฉพาะส่วนที่มีหลักฐาน ส่วนที่ยังไม่รู้แสดง “ข้อมูลไม่พอ” พร้อมหัวข้อที่ต้องเติม ตัวอย่าง: เสนอ Report ได้แต่เว้น L/M/H จนมีข้อเท็จจริงที่ใช้เลือกตามเกณฑ์ ไม่ใช้ระดับเริ่มต้นแทนส่วนที่ AI งดตอบ และไม่คำนวณ MD จากข้อเสนอที่ยังไม่ครบ
4. ปุ่ม “ให้ Jev ช่วยประเมิน” อยู่ในหน้าตรวจรายการก่อนสร้างโครงการ วิเคราะห์เฉพาะแถวที่ผู้ใช้เลือก รอบนี้ไม่เพิ่มปุ่มในหน้ารายการงานที่บันทึกแล้ว
5. แสดงค่าที่เลือกไว้เทียบกับคำแนะนำก่อนใช้ผล มีปุ่มยอมรับรายแถว และยอมรับรวมเฉพาะแถวที่ผู้ใช้เลือกซึ่งข้อมูลครบ แถว “ข้อมูลไม่พอ” ยังรอตรวจ คำแนะนำไม่ทับค่าของผู้ใช้ก่อนกดยอมรับ
6. งาน SAP/Vendor/Migration ให้ Jev เสนอเฉพาะ Activity ไม่เสนอ L/M/H หรือ MD ตาม generic Matrix ผู้ประเมินยังลง MD รวมตามบทบาทเอง กิจกรรมที่ไม่ตรงกับ Matrix ต้องงดจับคู่ ไม่บังคับเลือกกิจกรรมใกล้เคียง
7. ยังไม่มี TypeSafe API key ให้เตรียมระบบและทดสอบด้วยข้อมูลจำลองก่อน แล้วเชื่อม API เมื่อมี key โดยตั้งค่าฝั่ง server ไม่ส่ง key ในแชต ข้อมูลจำลองใช้ในการทดสอบและต้องไม่แสดงเป็นคำแนะนำจริงจาก Jev
8. หากข้อมูลรายการเปลี่ยนหลังยอมรับคำแนะนำ ให้คง Activity/ระดับที่ผู้ใช้ยอมรับไว้และแสดงคำเตือนว่าข้อมูลเปลี่ยน ผู้ใช้เลือกเองว่าจะประเมินใหม่หรือคงค่าเดิม ไม่บังคับประเมินใหม่และไม่ล้างค่าที่เลือกไว้ ข้อนี้เปลี่ยนพฤติกรรมของค่าที่ยอมรับแล้วจากการปฏิเสธข้อเสนอเก่าที่เตรียมไว้เดิม; คำแนะนำที่ยังไม่ยอมรับยังต้องตรวจว่าอ้างอิงข้อมูลปัจจุบันก่อนใช้
9. เมื่อสร้างโครงการ ให้เก็บคำแนะนำที่นำไปใช้ ข้อมูลประกอบที่ใช้เสนอ ผู้ยืนยัน และเวลายืนยันไว้กับรายการ เพื่อย้อนตรวจที่มาของ Activity/ระดับได้ แม้รายละเอียดภายหลังเปลี่ยนแล้ว ข้อมูลประกอบเดิมต้องไม่ถูกเขียนทับด้วยข้อมูลปัจจุบัน
10. วิเคราะห์ครั้งละไม่เกิน 20 รายการเป็นค่าเริ่มต้น และปรับจำนวนได้ผ่าน config ฝั่ง server หน้าจออ่านค่าที่ตั้งไว้เพื่อแจ้งจำนวนสูงสุดและแบ่งชุดเมื่อเลือกเกิน ไม่กำหนด 20 ตายตัวเฉพาะใน UI ฝั่ง server ต้องตรวจขีดจำกัดด้วย
11. เมื่อเลือกเกินขนาดชุด ให้แบ่งชุดและเรียกต่ออัตโนมัติ แสดงความคืบหน้าและมีปุ่มหยุด การหยุดต้องไม่เริ่มชุดถัดไปและรักษาผลที่เสร็จแล้ว การหยุดไม่รับประกันว่าจะยกเลิกค่าใช้จ่ายของคำขอที่ส่งไปแล้ว

MD ของ Matrix profiles คำนวณตาม Activity/ระดับ/จำนวนและตัวคูณของระบบเดิมหลังยืนยัน ส่วน SAP/Vendor/Migration ใช้แรงงานตามบทบาทตามพฤติกรรมเดิม การยอมรับคำแนะนำไม่เท่ากับการยืนยัน Baseline ก่อนปรับงบของหลักฐานเก่า

## ขอบเขตการพัฒนารอบแรก

เตรียมการเรียก Jev ผ่าน server, การตั้งค่า API key/model/ขนาดชุด, ปุ่มช่วยประเมินและการแสดงคำแนะนำในหน้าตรวจรายการ Excel, การยอมรับรายแถวหรือรวม, การเตือนเมื่อข้อมูลเปลี่ยน และการบันทึกประวัติพร้อมสร้างโครงการ ทดสอบด้วยข้อมูลจำลองที่แยกจากการใช้งานจริง เมื่อยังไม่มี key หน้าจอต้องแจ้งว่ายังไม่ได้ตั้งค่าการเชื่อมต่อ ไม่แสดงข้อมูลจำลองเป็นผลจริงจาก Jev

ข้อจำกัด: การทดสอบ API จริงและคุณภาพการเลือก Activity/ระดับด้วย Jev ต้องทำหลังมี API key ผลทดสอบจำลองยืนยันได้เฉพาะพฤติกรรมระบบและสัญญาข้อมูล ไม่ยืนยันความแม่นยำของโมเดล
