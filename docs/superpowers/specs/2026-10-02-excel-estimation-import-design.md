# Excel → รายการงาน → ประเมิน → Export

แบบได้รับการยืนยันจากเจ้าของงานวันที่ 2 ตุลาคม 2026 หลังเสนอหน้าอัปโหลดและตรวจรายการก่อนสร้างโครงการ พัฒนาบน `codex/excel-estimation-import` ต่อจาก historical matrix profiles

## พฤติกรรมที่ต้องได้

เข้าจากหน้าโครงการไป “นำเข้าจาก Excel” อัปโหลดไฟล์ `.xlsx` รูปแบบเดียวกับตัวอย่างใน `pttdigitalMD` ซึ่งแต่ละไฟล์มีชีตและตำแหน่งคอลัมน์ต่างกัน ผู้ใช้เลือกชีต ช่วงแถว คอลัมน์รายละเอียด และคอลัมน์เสริม Phase, จำนวน, Deliverables, Due date ได้ แสดงตารางต้นทางก่อนสร้างรายการ ไม่นำค่า MD ราคา Commercial หรือ Actual จากไฟล์มาใช้

อ่านเซลล์รวม: Phase อ้างอิงค่าของเซลล์ต้นทางได้ แต่รายละเอียดจาก merged cell ต้องเป็นรายการเดียว ไม่ทำซ้ำทุกแถว ชีตซ่อนแสดงสถานะและให้ผู้ใช้เลือกเอง ไม่เลือกข้อมูลซ่อนเป็นค่าเริ่มต้น สูตรไม่ถูกคำนวณใหม่ ใช้ cached result ถ้ามี; ไม่มี result ต้องแสดงข้อสังเกต ไม่อ่านสูตรเป็นเนื้องาน

ตรวจรายการ: แก้ Phase, รายละเอียด, จำนวน, Deliverables, Due date; เลือก/ตัดแถวออก; จับคู่ Activity และเลือก L/M/H สำหรับ Matrix; เลือก delivery profile ต่อกลุ่มงาน SAP/Vendor/Migration ประเมิน MD ตามบทบาทต่อในหน้ารายการ แถวว่างไม่สร้างรายการ หัวข้อ/ยอดรวมจะถูกเตือนและไม่เลือกในเบื้องต้น แต่ผู้ใช้ตรวจและเลือกเองได้ จำนวนที่ผิดไม่เปลี่ยนเงียบ ๆ เป็น 1 ส่วนที่ไม่ map จำนวนใช้ 1 อย่างชัดเจน

สร้างโครงการใหม่แบบ draft ใน transaction เดียว ใช้บทบาทและอัตราเริ่มต้นแบบเดียวกับโครงการปกติ ผู้ใช้ตั้งชื่อ/รหัส/Technology Stack ได้ ก่อนจับคู่ Activity ไม่มี MD และแสดงรอประเมิน; เมื่อจับคู่ใช้สูตร Matrix เดิม Qty และตัวคูณ Stack Activity แบบต่อโครงการบังคับ Qty=1 เฉพาะ Matrix profiles เก็บชื่อไฟล์/ชีต/แถว/คอลัมน์รายละเอียดและ SHA256 ใน sourceReference ไม่มีการยืนยัน historical Baseline อัตโนมัติ

หลังสร้างไป step 3 ประเมินแก้ไขรายการ รวมถึงจับคู่ Matrix รายการที่พักไว้ได้ เลือกทีม step 4 และสรุป/Export มาตรฐานเดิม ไม่มีการเขียนผลกลับลง Excel ต้นฉบับ

## ขอบเขตและการตรวจข้อมูล

ใช้ ExcelJS ฝั่ง server ซึ่งระบบมีอยู่แล้ว ส่งเฉพาะข้อความเซลล์และตำแหน่งกลับ client ไม่เก็บ workbook ถาวร อัปโหลดไม่เกิน 10 MiB จำนวนชีตไม่เกิน 50; ชีตที่เกินขนาดอ่านข้ามพร้อมอธิบาย (2,000 แถว/80 คอลัมน์), เซลล์มีข้อความไม่เกิน 200,000 ต่อ workbook จำกัดข้อความต่อเซลล์ 8,000 ตัวอักษรและแสดงข้อผิดพลาดแทนการตัดข้อมูลเงียบ ๆ JSON สร้างโครงการไม่เกิน 1,000 รายการและ 2 MiB ตรวจ writer role, same-origin, validation และ active master IDs ฝั่ง server; viewer เข้าไม่ได้ ไม่มี AI API call ในรอบนี้ ใช้การแยกค่าที่สังเกตจากต้นทางกับการตัดสินของผู้ประเมินตามแนว TypeSafe

ไม่อ่าน folder จากเครื่องผู้ใช้โดยตรงหรือ auto import ทั้ง folder ผู้ใช้เลือกไฟล์ในหน้าอัปโหลดได้ folder เป็นตัวอย่างรูปแบบสำหรับทดสอบ ไม่แก้ source workbook หรือข้อมูลโครงการเดิม ไม่เพิ่ม migration เพราะใช้ schema profiles/evidence ที่มีอยู่แล้ว

## การทดสอบ

ทดสอบ workbook synthetic ที่มีหลายชีต, merged phase/detail, สูตรที่มี/ไม่มีผล, ภาษาไทย, หัวข้อและ total, จำนวนผิด, worksheet ใหญ่และไฟล์เสีย ทดสอบ DB แยกใน temp: viewer/invalid master IDs ไม่สร้างข้อมูล; mixed profile; Matrix Qty×Stack; pending ไม่สร้าง MD; source evidence ไม่ confirmed; rollback เมื่อ input ไม่ถูกต้อง; Export เปิดกลับได้และมีรายการ/แหล่งอ้างอิงครบ ตรวจอ่านไฟล์จริงทั้ง 24 ไฟล์แบบ read-only ตรวจ UI upload→map→review→estimate→export กับ DB synthetic พร้อม typecheck, ESLint, regression และ build
