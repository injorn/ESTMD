01 / SCOPE DISCOVERY · 11 DIMENSIONS

เริ่มประเมิน MD ด้วย 11 Dimensions

กรอบตรวจความครบถ้วนของขอบเขต จากคำถามธุรกิจสู่รายการงานที่ประเมินได้

กรอบจากผู้ใช้ · Mapping เป็นข้อเสนอ
หนึ่งงานอาจเกี่ยวข้องหลายมิติ แต่คิด MD เพียงครั้งเดียว: ใช้ Dimensions เก็บข้อมูลและตรวจช่องว่าง แล้วแตก work item ที่มี ID, deliverable และผู้รับผิดชอบชัดเจน ไม่บวก MD แยก 11 มิติหรือใช้จำนวนมิติเป็นตัวคูณ
แต่ละมิติให้ระบุ “มีงาน”, “ไม่มีงานในขอบเขต” หรือ “รอข้อมูล” พร้อมผู้ยืนยัน; ข้อมูลที่ยังไม่ทราบไม่ใช่ effort เป็นศูนย์
1. เก็บขอบเขตตอบ 11 Dimensions
2. แตก Work Itemกำหนด ID / Deliverable
3. จับคู่ Activityเลือก Delivery Profile
4. ระบุ Qtyนับตามหน่วยงานจริง
5. เลือก L/M/Hหลักฐาน + เหตุผล
6. รวม MDแยกบทบาท / ตรวจซ้ำ

ข้อมูลหนึ่งรายการที่ควรได้: Work Item ID · Dimension ที่เกี่ยวข้อง · Module/Phase · รายละเอียด/Deliverable · Activity · Delivery Profile · Qty/หน่วย · ปัจจัยและระดับ · MD ตามบทบาท · In/Out of Scope · สมมติฐาน/ข้อมูลที่ขาด · ผู้ประเมิน/ผู้ยืนยัน

สูตรเมื่อใช้ Matrix: MD ต่อบทบาท = ค่า Matrix ของ Activity และระดับ × Qty × ตัวคูณที่มีผลกับบทบาทนั้น; บทบาทแบบ Phase คิดตามสัดส่วนตามการตั้งค่าโครงการ ส่วน SAP/Vendor/Migration ลง MD ตามบทบาทที่ประเมิน แล้วรวมและคิด Buffer แยกภายหลัง

ตัวอย่าง: ระบบขออนุมัติ + เชื่อม SAP + อบรม

ตัวอย่างสมมติสำหรับอธิบายวิธีใช้ ไม่ใช่ผลประเมินโครงการเก่า: business process/workflow มีอนุมัติหลายขั้น, integration มี mapping/validation ตามขอบเขตที่ชัด และ training เป็น workshop ที่ต้องเตรียมข้อมูล → แตกเป็น 3 รายการที่ไม่ซ้ำกัน ปรับ Qty/ระดับเพื่อดู MD รวมค่าเซลล์

แรงงานรวมเฉพาะ 3 รายการตัวอย่าง

กรอกจำนวนเต็มตั้งแต่ 1 ถึง 1,000 ในทุกรายการก่อนรวม MD

สมมติว่าแยก workflow/interface ออกจาก CRUD แล้ว ทุกบทบาทเป็น item-scoped, Qty เป็นหน่วยที่แตกต่างจริง, ตัวคูณ 1 และยังไม่คิด Phase ratio/Buffer ตัวอย่างนี้ผสม MD เดิมกับ MD เสนอของ Training และยังไม่มี Requirement/Design, หน้าจอ, Environment, Testing, คู่มือ หรือ Change Management จึงต้องเติมรายการเหล่านั้นก่อนสรุปทั้งโครงการ

02 / DECISION PRINCIPLES

เลือกระดับจากขอบเขตและปัจจัย

Activity เดิมแสดง MD จาก Matrix; งานใหม่แสดง MD เสนอพร้อมสมมติฐาน แยกจากมาตรฐานที่ใช้อยู่

1Low เมื่อทุกปัจจัยอยู่ใน Low

ใช้ pattern เดิม มีขอบเขตจำกัด และยืนยันได้ว่าไม่มีเงื่อนไข Medium หรือ High ที่เกี่ยวข้อง

2ใช้ระดับสูงสุดที่มีหลักฐาน

ไม่ต้องครบทุกข้อในระดับนั้น คำว่า SAP, MFA, Import หรือ Export เพียงคำเดียวไม่ใช่เหตุผลจัดเป็น High

3ข้อมูลไม่ครบ → รอตรวจทาน

ถามข้อมูลที่ขาดก่อนยืนยัน จำนวนงานใช้กำหนด Qty ส่วนความซับซ้อนใช้เลือก L/M/H ต่อหน่วยงาน

สถานะข้อเสนอ: ข้อความ L/M/H ด้านล่างเป็นร่างออกแบบจากลักษณะงานที่พบ ไม่ใช่ระดับที่เอกสารเก่ายืนยันไว้ และยังไม่ได้เปลี่ยนมาตรฐานในระบบ สำหรับ SAP, Vendor และ Migration/Rollout ให้ลง MD ตามบทบาทตามรูปแบบการส่งมอบ

ร่าง L/M/H ทุกกลุ่มรอเจ้าของมาตรฐานยืนยัน

เนื้อหาที่พิมพ์เป็นรายการตามตัวกรองที่เลือก ณ เวลากดพิมพ์

06 / IMPLEMENTATION ORDER

ลำดับการนำไปใช้

ยืนยันเกณฑ์และหน่วยนับก่อนปรับการประเมิน

PHASE 01

เติม Activity ที่มีหลักฐานชัด

Workflow, Notification, Export, SSO/Permission, Migration/Upgrade, Security และ Deploy

  • ยืนยันร่าง L/M/H และข้อมูลที่ต้องถาม
  • แยกหน่วยนับและขอบเขตที่คิดร่วมกัน
PHASE 02

ขยายเกณฑ์ที่ระบบใช้แล้ว

Interface, Job, Dashboard/Report, Import, Testing และ Requirement/Design

  • เพิ่มปัจจัยที่เกณฑ์เดิมยังไม่ครอบคลุม
  • ทดสอบเทียบตัวอย่างพร้อมเหตุผลของผู้ประเมิน
PHASE 03

เพิ่มงานใหม่และใช้ข้อมูลร่วมกัน

Performance Tuning, Load Test และ Training พร้อมเกณฑ์เฉพาะของ SAP/Rollout

  • ยืนยันค่า MD ตามบทบาทด้วยหลักฐานแยก
  • หน้าเกณฑ์, AI และ Excel ใช้ข้อมูลชุดเดียวกัน

สิ่งที่หลักฐานบอกได้

  • มีงานลักษณะใด ปัจจัยใดและสิ่งส่งมอบใดที่เกณฑ์ควรครอบคลุม
  • จำนวน 24 ไฟล์ไม่เท่ากับ 24 ตัวอย่างอิสระ: RCP และ SAP GRC มีข้อมูลเซลล์เหมือนกัน
  • 6 ไฟล์มีเพียง resource/cost เป็นหลัก จึงไม่กำหนดเกณฑ์จากชื่อโครงการ

สิ่งที่ต้องยืนยันก่อนใช้

  • ช่วงตัวเลข L/M/H, หน่วยนับใหม่ และขอบเขตที่คิดร่วมกัน
  • MD ประเมินตามเนื้องานก่อนปรับงบ ไม่ถือ MD เก่าเป็น MD ใช้จริง
  • In Scope / Out of Scope และ revision ที่ยืนยันแล้ว; การอ่านครั้งนี้ไม่ตีความรูปภาพและไม่คำนวณสูตรใหม่
